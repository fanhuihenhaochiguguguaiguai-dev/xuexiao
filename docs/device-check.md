# 手机自动检测

继续使用原入口：https://henan-jingmao-campus-play.earthyaspen11.chatgpt.site 。已开放公开试玩，无需使用项目所有者的 ChatGPT 账号。

手机横屏打开网页，点击“开始探索”。若画面异常，可点击左下角“使用兼容模式”重新加载为WebGL 2。默认勾选首次自动检测：约5秒准备，再依次查看图书馆、道路、湖面和操场各10秒，共约45秒。无需安装开发工具、输入代码或手动移动人物。检测时可点击“跳过检测”。

结束后自动显示结果；右上角“检测”可随时查看、重新检测或导出 JSON。报告只保存在这台设备的浏览器中，网站不会自动上传设备报告。清理浏览器数据会删除本机记录。相同版本已经完成检测时不会每次重跑。

当前默认均衡档为1.0倍渲染、1024阴影和手机30FPS上限目标。固定检测临时使用省电档（0.85倍）并提高采样帧率上限；报告中的FPS只适用于记录的检测配置，结束后恢复原设置。检测时可跳过；它不能替代正常画质下的长时间手机温升验收。

## 报告内容

- 实际后端：WebGPU 或 WebGL 2，不能只凭 `navigator.gpu` 存在判断。
- 适配器证据：优先读取实际 GPUDevice 的信息；另行请求的兼容性适配器只作为探测线索，不能证明实际设备使用情况。
- 软件渲染、回退适配器、设备丢失、图形校验错误，以及浏览器未开放详细硬件信息的情况。
- 固定画质、画布尺寸、像素比例、四个场景的真实帧数、采样时长、平均 FPS、P95/P99 帧耗时和超过50ms的帧占比。
- 中断、取消与初始化失败原因；采样不足不报通过。

帧耗时来自实际 `postrender` 间隔，包含CPU、GPU、浏览器和显示调度。没有把更新函数的限幅 `dt`、模拟步数或推测的 GPU 耗时当作帧率。报告中的“1% low”指1000/P99帧耗时，作为较慢帧的指示，短样本时不宜过度解读。

当前初步门槛：每个场景平均至少30 FPS，P95帧耗时不超过50ms，且无设备丢失或运行错误。达到帧率要求但使用WebGL 2时，只记为该后端的性能结果。检测到软件适配器，或实际设备硬件信息不足时，不记为硬件WebGPU验收通过。

测试期间停止自适应分辨率变化，暂时禁用人物输入并沿固定镜头路线渲染真实校园。结束后恢复原来的画质、位置与镜头。切到后台、窗口大小改变或旋转屏幕会终止并记录中断，不把后台节流或不同分辨率混成一份有效报告。

## 能力边界

浏览器不能可靠读取设备出厂年份。项目不以2018年前设备为优化目标，但不能凭用户代理字符串伪造一个年款判定；是否支持WebGPU和运行是否达标以实际能力与采样为准。

45秒测试用于发现明显兼容性及帧率问题，不覆盖持续发热、耗电、长时间稳定性、建筑真实性或所有触控操作。手机实体设备的运行结果仍需由手机实际打开网页产生，AI不能从云端直接读取用户手机GPU。

v0.6完整检测流程已验证，包含自适应贴图预算恢复。两核云端软件WebGL2每阶段约0.48–0.54 FPS，采样帧数不足，性能未达标；不能推断安卓手机帧率。另做软件WebGPU实验：适配器可初始化，离屏红色清屏回读正确，但该云环境的WebGPU画布截图为空；没有把“初始化成功”写成视觉通过。详情见 `reports/browser-device-check.json`、`reports/webgpu-canary.json` 和 `reports/webgpu-render-validation.json`。
